# Main 320维与3曲/80000预算实测

2026-10-14。基于v3 main `8752622`及保留的未提交修改；参数基线来自当前源码，不能等同于历史ckpt30绑定配方。本次只实现配置及独立诊断，没有启动正式训练或改写既有资产。

后续用户已确定覆盖配置采用3曲/80000、M内部chunk预算32768、最大LR6e-4，结构保持本页方案。下述CUDA测量记录仍对应当时最大LR5e-4及200步warmup，不改写为6e-4的训练证据。当前main保留每16拍一份plan12。

实验覆盖配置为 `configs/joint-main320-z4-plan16-gt.json`：E/D/M均8头、每头40维、总维320；E和M前段FFN1280，D/M每专家640；M由6层增加至8层，前2层Router不动、后段4→6层。D的Z为320维，NOTE/ROUTE拼接配额同比扩宽。P/R专属内部宽度和字段readout维数保持原值。外层最多3个完整音频组、预算80000，BF16和workers12等既有配方保持。

`entry.CONFIG` 默认值未整体替换。M内部chunk新增显式null支持，整数仍保持原分块、完整历史、顺序、分母和单块/多块反向路径。独立阶段二row_budget仍为8192；用户已选择本次联合实验M内部chunk预算32768。

## 平均每轮更新及预算

沿用已有训练计划1493音频组、1622谱、40625基础窗，只读计划和v5长度元数据，枚举150轮固定seed洗牌顺序。每完整逻辑batch一次optimizer update，累积仍为1。当前默认绝对停止90轮，因此另列前90轮均值；150轮是cosine调度范围及极端批次枚举范围，没有实际执行150轮训练。

| 曲目上限 / 总预算 | 前90轮平均更新 | 150轮平均更新 | 各轮最小–最大 | 平均预算利用率 |
|---|---:|---:|---:|---:|
| 2 / 45056 | 869.12 | 869.47 | 853–883 | 75.83% |
| 3 / 65536 | 547.20 | 547.33 | 541–556 | 82.82% |

80000相对65536每轮更新再少8.62%，相对原2曲/45056少42.48%。这只是组批更新数变化，不等同于整轮耗时下降比例。1493组最多3组一批的理论下界是每轮498次，当前平均500.14次已接近该下界。

80000平均实际调度proxy为59398.40（74.25%），并不会经常填满；98.59%的batch已满3组。65536时预算对下一完整组更常构成限制；升至80000后，仅3曲上限阻止下一组的边界占53.33%，主要限制转为曲目数。保留完整组与既有顺序，不拆曲或重新排序凑满。

## CUDA容量与速度

RTX4090D 24564MiB、Torch2.11.0+cu130，BF16、workers12。每自然batch/预算独立进程，2次预热、5次计时；表中为同步完整update墙钟中位数，含H2D、前反向、clip、fused AdamW及scheduler，不含DataLoader等待和模型/optimizer/scheduler/RNG恢复。峰值LR配置5e-4，实际诊断仍保留200步warmup。

新预算新增的极端全部重新实测；不重跑未变化架构的资格审计。65536阶段已确认五模块非零梯度/更新，E/D各前向与共享反向一次；新两层均59/59参数张量有非零梯度。相关原始证据位于父目录results。

建议M内部预算32768：只拆罕见长尾，普通99.673%与取消预算走同一单块路径。80000下新增最大E窗口数102（原65536为84），因此外层预算扩大会同时增加E成本；M预算不能限制E分支显存。
