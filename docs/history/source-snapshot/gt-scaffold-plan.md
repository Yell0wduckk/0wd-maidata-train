## 2. 骨架条件与模型接口

### 骨架数据

训练时从已读取的 GT 目标行提取当前窗口的骨架：

- 每个 MOMENT 的绝对 tick、对应 NOTE 数量及有效 mask。
- `SLIDE_BRANCH` 不计入 NOTE 数量；不提供分支数量或 ownership。
- 不提供未来的类型、键位、路径、修饰、时长或原始 NOTE 行特征。
- 窗口按原16拍半开区间划分；保留既有 NOTE 增强、视图、occurrence 和原始行映射。
- 不把四拍历史副本计入骨架，不跨谱面／视图混读。
- 只在正常数据读取时派生，不重建 Mel、GT、Physical、几何或固定数据计划。

新增训练条件表达：窗口骨架、query 所属窗口，以及由已接受前缀计算的骨架游标和剩余 NOTE 数量。训练与推理使用同一控制器计算游标与合法事件集合，不能借用未知的下一行配置。

### 骨架编码与注入

新增独立的节奏骨架 encoder：

- 每个 MOMENT 一个 token，输入窗口内拍位置、相邻 MOMENT 间隔和 `log1p(NOTE数量)`；间隔均由已公开的骨架计算。
- 宽度128、两层 Transformer、四头、FFN512，dropout沿用父模型。
- 当前窗口内部双向编码，允许读取整个窗口的未来骨架；这属于明确提供的条件。
- 空骨架通过有效 mask 表示，不使用有效 dummy token。

八层 decoder 和 router 均新增独立骨架交叉注意力，放在音频交叉注意力之后、FFN/MMoE之前：

- decoder 宽度256、八头；router 保持128宽度、四头。
- 每层采用 pre-norm、残差和父版 dropout，不增加初始关闭的条件 gate。
- 每个唯一窗口的骨架只编码一次，各层 K/V 分别投影一次；按窗口批量处理 query，不逐行复制骨架或循环调用注意力。
- 使用一致的拍坐标；decoder 使用绝对拍，router 按其原局部坐标显式转换。
- 新增模块采用隔离 RNG 初始化，不改变父版保留模块的固定种子初值。

保留父版八层自回归 decoder、全部因果谱面历史、全曲 P0、局部 router，以及22拍音频编码与中央16拍拼接。旧 latent 路径继续冻结并跳过。历史 K/V 保留其原所属窗口的骨架条件，不在切窗时重新施加条件。

## 3. 配置训练、推理与恢复

### 只学习未知决策

模型继续预测 NOTE 类型、位置、修饰、HOLD／SLIDE时长、路径，以及分支继续／结束等未知配置。

骨架控制器负责：

- 在指定时刻插入 MOMENT。
- 保证每个 MOMENT 恰好产生指定数量的 NOTE。
- 允许符合语法的 SLIDE_BRANCH 附着于已生成 NOTE；分支不消耗 NOTE 名额。
- 在该窗口骨架完成且当前分支关闭后输出 `SEGMENT_END`。
- 对空骨架窗口直接结束，不新增 NOTE。

事件支持集取“原语法支持∩骨架支持”。仍有多个合法选择时继续训练 router／条件事件头；只有一个选择时不计算该决定的预测损失。

损失调整：

- 删除 MOMENT delta 的预测损失及对应 Physical 概率项；已知时间仍用于输入、位置权重和 Physical 判定。
- 保留 NOTE／branch 语义损失、原字段权重和未知结构决策的原系数。
- 确定事件项置零，保留父版原事件行分母；不把删除的时间或事件权重重新分配给其他项。
- Physical 只覆盖仍由模型预测的支持，保留原类别权重、固定四类 reduction 和988步 warmup。
- 不再执行无消费者的 delta 预测；其专用参数及完全不使用的输出头冻结。持续时间预测头仍正常训练。
- 共享主干、八层 MMoE 和 router 不因部分时间决策已知而整体冻结。

原音乐配置目标、增强顺序及 Physical source-row 映射不变。报告保留的配置监督量、可学习事件量和被取消的确定项数量；新旧总 loss 不作直接质量比较。

### 固定骨架推理

新增 `--rhythm-scaffold <文件>`，本实验推理必须提供。文件只包含谱面身份、时间条件、窗口边界和 MOMENT 时刻／NOTE数量，不包含未来配置。

提供从既有 GT 提取该文件的入口，仅处理请求的谱面。生成时：

- 历史配置全部来自已生成结果，不使用 GT NOTE 前缀。
- 普通与流式接口使用相同骨架控制器。
- 快照、Physical 回滚和 `replay_last` 同步恢复骨架游标、NOTE计数、分支状态及 decoder/router K/V。
- 骨架编码和投影在窗口内复用，回滚不重建或改变骨架。
- 保留父版 Physical／MiaCode 规则、分支上限及必要 bypass 记录；不能通过移动 MOMENT、少生成 NOTE 或提前结束来逃避失败。
- 行数预算须容纳骨架必需行，并受既有分支上限约束；预算耗尽或无解时明确报告失败，不将缺失骨架的截断结果算作成功。

中央版本升为 **35.00**。训练／推理仅接受本版骨架条件合同，历史物化范围扩展；不导入旧 A 权重或伪装同语义续训。完整轮恢复继续绑定模型、实际 optimizer 参数集合、scheduler、游标、RNG和固定计划，不新增源码 SHA 门禁。

## 4. 必要 CPU 验证与主会话复核

仅运行受影响 CPU 测试，临时产物全部放在新 D 盘 worktree；不运行独立 CUDA 诊断、单 batch 重放或 profiler。

必要验证：

- **骨架提取**：同拍多 NOTE、分支不计数、空窗、边界音符、BPM变化；提取结果不受 NOTE 重排影响。
- **信息隔离**：未来配置改变而时刻／数量不变时，骨架不变且此前预测不受影响；允许未来骨架影响当前预测；其他窗口、歌曲、谱面和视图不得混入条件。
- **模型与复用**：骨架 encoder、交叉注意力、音频及八层 decoder 获得梯度；latent 路径不执行；共享编码和 K/V 投影次数正确。
- **目标正确性**：未知字段及权重保持；确定时间／事件无损失梯度；未知分支决策保留；与独立小样本参考核对 loss 和 Physical 支持。
- **训练／推理一致性**：固定条件、关闭 dropout 后，teacher forcing 与逐行推理对齐；跨窗、回滚、重放及流式结果一致。
- **严格遵循骨架**：时刻和 NOTE 数量逐项一致；覆盖分支生成、全部空窗和无法完成的失败路径。
- **恢复与入口**：小夹具贯通更新→完整轮保存→恢复→下一次更新→固定骨架推理；拒绝旧版或错误计划；正式入口只包含 A90 和指定五首生成。

主会话独立阅读 diff 和证据，重点复核未来配置隔离、事件控制器、损失支持、分支与回滚。只复测修复涉及的内容，不增加质量、速度或 loss 门槛。
