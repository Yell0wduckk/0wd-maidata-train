# Frozen Draft and Planner export

`python -m maidata.decoder_training.dp_cache --config CONFIG.json --p0-cache P0_ROOT --output NEW_OUTPUT`

Consumes the existing complete P0 manifest and banks. A frozen-E Drafter trained from stage-II P0 reuses those original banks through its recorded `audio_producer` identity; the stage-II P0 checkpoint and the trained stage-I D/P checkpoint are intentionally different. This path reads recorded metadata without rehashing accepted catalogs or banks. Older joint-E producers retain their existing matching-P0 contract. The independent FrozenProducer owns E/D/P; only D and P run in eval/no_grad (CUDA BF16 for experiments, CPU FP32 for tests). Encoder stays on CPU; Decoder is not constructed. Uses 12 workers by default. Does not rebuild audio, fields, Physical or P0.

Each audio variant has one bank containing full-song Z values/beats/valid for unique exact difficulty/level conditions, chart-to-condition mapping, and predicted plan12 for every unique chart window including the complete empty tail. Complex extra occurrences reuse these window identities. Z includes full Draft coverage so future consumers can select their own Decoder context. No GT planner labels enter prediction. Plan input is target-only Z. Both train and validation splits are exported without changing their membership.

Schema `maidata.frozen-draft-planner.v2`, representation `final-normalized-beat-z`; width is recorded explicitly. Manifest records the D/P producer and its frozen P0 identity when applicable, precision, source and generated-file hashes. Newly generated outputs are checked for finite values and saved atomically; first-bank tensor roundtrip is exact. Existing accepted payloads are only read as needed, without a separate recursive rehash.

Export does not start training. Both joint stage-II training and [frozen Decoder adaptation](decoder-frozen-adaptation.md) read Z through `decoder_train_dp_cache`; the latter reads a separate per-window P0 cache preserving M's original audio context, not this full-song D input. Neither executes D/P or fills missing caches online. GT plan remains a separate accepted cache. Cache production remains separate; see [Decoder training](decoder-training.md).
