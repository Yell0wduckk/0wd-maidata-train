# Decoder ROUTE 软标签：未来方向

本文件记录尚未实施的讨论方向，不是当前训练配方。本次仅修改
[Draft的37类接受度监督](draft-route37.md)；主Decoder的71类ROUTE输出、硬标签监督、
Judge、Trajectory、Physical和推理保持现状。

## 从37类接受度到71类相似度

Draft的固定接受度矩阵 `A [37,37]` 以GT为行、预测为列，保留非对称关系。
未来Decoder可使用既有71→37映射 `g` 将矩阵展开为71类，再依据精确route的
终点和运动方向进行二次衰减：

\[
s_{y,j}=A_{g(y),g(j)}\,F_{\mathrm{endpoint}}(y,j)\,F_{\mathrm{direction}}(y,j).
\]

同组镜像也需要方向修正，不能因为读取矩阵对角值1就视为完全等价。
终点不同的route，以及终点相同但方向不同的 `1p5/1q5`、`1s5/1z5` 等，
应由后续选定的衰减函数区分。具体函数、参数和数值仍待讨论。

## 非GT概率分配与ε

先排除基础语法不允许的候选，再排除GT。仅对剩余正相似度按和归一化，
不使用softmax，使接受度0仍为0。对GT类别 `y`，候选集合为 `C_y`：

\[
q_y=1-\varepsilon_y,\qquad
q_j=\varepsilon_y\frac{s_{y,j}}{\sum_{k\in C_y}s_{y,k}}
\quad(j\in C_y).
\]

其他类别概率为0。没有剩余正相似度时令 `ε_y=0`，退回硬GT；WiFi等无相似
候选的类别可使用这一路径。总平滑量由 `ε_y` 控制，相似度只决定其在非GT候选
中的分配。

ε可以按GT类别设置。相似候选较多的类别是否分配更多ε，以及依据正相似邻居数量、
相似度总量还是人工类别表确定ε，均尚未定公式和数值。固定类别ε与方向相似度
预计算后可查表/广播，不增加网络前向；相对固定ε的额外计算很小，但尚未测量实际耗时。

## 后续监督调整

未来拟使用软标签CE `-sum_j q_j log(p_j)` 替换ROUTE硬NLL，不额外叠加另一份
ROUTE硬NLL；Judge、Trajectory和Physical暂时保留原监督。接受度矩阵本身、
Draft的接受度边缘概率损失和Decoder的归一化软标签是不同接口，不能直接互换。

实施前仍需确定方向衰减函数及分类别ε策略。本文件不启用新配置，不改变现有
checkpoint、缓存、训练或推理行为。
